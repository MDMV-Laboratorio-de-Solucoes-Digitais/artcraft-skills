## Workflow Rules (MANDATORY for execution)

- **W0 Template/scaffold first**: All code that can be generated by a template/scaffold MUST be written (for example, by LSP code actions / IDE scaffolds) **BEFORE** writing it by hand. Record in the commit message when a scaffold/LSP action was used.
- **W1 TDD RED gate**: Test tasks are written first. Property-based tests are used where applicable, testing invariants as much as possible. **All RED-phase tests MUST be written and observed NOT passing (or failing for the intended missing behavior) BEFORE any implementation task begins.** Implementation tasks are blocked until the RED gate task is satisfied.
- **W2 Parallel waves / `[P]`**: Tasks marked `[P]` touch disjoint files and have no dependency on incomplete tasks; execute via subagent-driven development in waves. Tasks sharing context/file ownership reuse the **same subagent**. Shared tooling is used by only one agent at a time; if a long-running tool blocks others, agents wait in queue. **NEVER kill/interrupt/bypass a tool started by another agent/thread/process/project.**
- **W3 Verification-only attestation**: Verification tasks are performed at the end. **ONLY these verification tasks attest to the success and completeness of the implementation, NEVER the agent itself.**
- **W4 Deterministic hook (per-file edit completion)**: Whenever editing a file finishes, create an **atomic conventional commit** with a detailed summary of the edits made. Scope commits to files changed for that task/wave; do not include unrelated pre-existing worktree changes.

- **[P]**: Parallelizable (different files, no dependency on incomplete tasks).
- **[Story]**: `[US1]`, `[US2]`, `[US3]` only in user-story phases.
